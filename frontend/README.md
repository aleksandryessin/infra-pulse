## Запуск

Frontend не содержит демонстрационных данных: synthetic ответы отдаёт backend
в `INFRA_MODE=fixture`. Ошибка API показывается как ошибка и никогда не
подменяется fixture.

```sh
# терминал 1, из корня репозитория: API на 8000 с synthetic fixture
INFRA_MODE=fixture make api
# терминал 2
cd frontend
npm ci
VITE_DATA_MODE=fixture npm run dev
```

Откройте http://127.0.0.1:5173/ — приложение перенаправляет на `/forecast`.
Порт 5173 фиксирован. Vite проксирует `/api` и `/health` на
`http://127.0.0.1:8000` (переопределение — `API_PROXY_TARGET`); в Docker nginx
проксирует их на `api:8000`, а `try_files` отдаёт `index.html` для SPA-маршрутов.

`VITE_DATA_MODE` (`fixture` | `replay` | `received`) задаёт сборку: подпись режима
до первого ответа сервера, включение страниц исходных сообщений (`replay`,
`received`) и проверочную подмену роли (`fixture`). Режим на экране берётся из
поля `mode` ответа `/forecast-state`; подпись в шапке видят все только у `fixture` и
`replay`, рабочие `received`/`live` — только администратор (`headerModeLabel`, docs/UI.md).
`VITE_GRAFANA_LINK=1` включает ссылку «Графики сигналов» (`GRAFANA_SIGNALS_URL`: дашборд
текстовых состояний за 21.05–01.06.2026 МСК).

### Роли без входа (dev-override)

Пока B3 не включил LDAP, backend работает в `auth_mode=dev_stub`: все запросы
идут от локального оператора со всеми ролями. В dev-сборке или при
`VITE_DATA_MODE=fixture`, если `auth_source` не `ldap`, в меню слева есть
«Проверка ролей»; то же задаёт параметр `?dev_role=dispatcher|analyst|admin`
(хранится в `sessionStorage` вкладки). Подмена только сужает роли сессии на
клиенте; права по-прежнему проверяет сервер (403). Для серверной проверки роли
используйте FastAPI `dependency_overrides` для `current_actor` в локальном
запуске; с LDAP (B3) подмена отключается.

### Проверки

```sh
npm run build          # tsc --noEmit + vite build
npm test               # чистые функции: порядок прогноза, раскладка мнемосхемы (в т. ч. 40 линий, ПК 0–601), колокольчик, HTTP-клиент
npm run check:words    # после build: запрещённые слова вне «Исследования» в бандле
npm run generate:api   # типы из ../contracts/openapi.json; schema.d.ts вручную не править
```

`check:words` ищет «вероятность», «авария», «оракул», «recall», «CatBoost»,
«фолд», «поколение», «корзина», «ввод ПК», прежний термин «фидер» и др. во всех чанках, кроме
`ResearchPage-*`. Единственное исключение — утверждённая оговорка строки частоты
«…это не вероятность для объекта» (`src/shared/config/wording.ts`).

## Разделы

| Маршрут | Раздел | Право |
| --- | --- | --- |
| `/forecast` | «Сейчас» (тревожные сообщения СМВУ за сутки) и 10 карточек прогноза | `read` |
| `/forecast/:id` | Широкая карточка C4 с решением; `?back=` — куда вернуться | `read`, решение — `decide` |
| `/scheme` | Мнемосхема объекта, `?object=&sel=` — объект, выбор и полоса сведений | `read` |
| `/journal` | Счётчики и записи; `?state=&from=&to=&object=` | `read` |
| `/journal/:position` | Снимок карточки на момент выдачи | `read` |
| `/research` | Области прогноза, P/R с ДИ, «прогноз против факта» | `research` |
| `/upload` | Загрузка CSV, этапы, отчёт, история | `import` |
| `/login` | Вход через каталог (B3) | — |
| `/queue`, `/queue/journal` | Исходные сообщения и заметки (только replay/received) | `read` |

Прямой URL раздела без права показывает «Нет доступа» и не вызывает API.
Прежняя `/map` перенаправляется на `/scheme` (объект из ссылки сохраняется);
`/drafts`, synthetic `mocks/data.ts` и `DecisionsProvider` на `sessionStorage`
удалены — решения читаются и пишутся через API.

## Вход, CSRF и ошибки

- Сессия — cookie (`credentials: same-origin`). Ответ 401 любого запроса ведёт на
  `/login?next=…`; после входа возвращает на исходный адрес.
- Каждый POST несёт `X-CSRF-Token`: значение cookie `__Host-infrapulse-csrf`, которую
  B3 ставит при входе (HttpOnly у неё нет, у cookie сессии — есть), либо заголовка
  `X-CSRF-Token` последнего ответа сервера, иначе `1` — до входа B3 принимает любое
  непустое значение. Cookie с префиксом `__Host-` работают только по HTTPS (публичный
  стенд за Caddy).
- 403, 409, 413, 422, 429 и 503 показываются текстом рядом с кодом
  (`src/api/http.ts`, `describeApiError`). В `dev_stub` экран входа пишет
  «Вход не настроен».

## Опрос и уведомления

`/forecast-state` опрашивается раз в 30 с и при возврате к вкладке; списки
перечитываются только при смене публикации. В шапке — два среза: «Прогноз: данные
до …» (`forecast_data_as_of`) и «Сообщения источника: до …» (`source_messages_as_of`);
при сбое опроса видна строка об устаревании. Колокольчик читает серверный
`GET /api/v1/notifications` (N1, C0.5) за сутки до среза прогноза: только
`critical_alarm`, в порядке ответа, все строки (до 50) с прокруткой; серии и повторы одного
датчика за час по `row_kind` одной раскрываемой строкой («похоже на ППР или ТО — сверить с
графиком», «… ×N» и под ней «с ЧЧ:ММ по ЧЧ:ММ»); на «Схему» ведут только строки объектов из `/schemes`,
у прочих — «схемы нет» с пояснением; метка группы «Пожар»,
«Газ» или «Затопление» — на клиенте по `rule_id` (`ALARM_GROUP_LABELS` в
`src/shared/config/labels.ts`), внизу подпись о составе списка, `policy_caption` — в
подсказке. Клиентские правила `src/shared/config/notifications.ts` нужны только блоку
«Сейчас», когда в данных нет отметки «тревожное». «новые: N» у пункта «Прогноз» — открытые карточки, не
виденные в списке. Прочитанное хранится в `localStorage` (`infra-notifications-v3`).

## Исходные сообщения replay/received

Страницы прежней операционной очереди сохранены как отдельный чанк на
`/queue` (исходные сообщения и локальные заметки) и `/queue/journal`
(журнал заметок и раздел «Исходные сообщения»). Они работают только с
PostgreSQL в `INFRA_MODE=replay|received`:

```sh
VITE_DATA_MODE=replay npm run dev     # или received
```

Ссылки на них ведут из блока «Сейчас», полосы сведений схемы и колокольчика.
Их подробное поведение (закрепление `as_of` и `received_watermark`, фильтры
кандидатов, заметки) описано в истории [UI](../docs/UI.md#исходные-сообщения-replayreceived-до-f1).
Прежняя административная схема `/map` удалена вместе с её фильтрами групп;
визуальное соответствие этих страниц C4 не проверялось.
