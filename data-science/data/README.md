# Локальные исследовательские данные

[parquet/](parquet/README.md) — канонический вход EDA: versioned snapshots с
manifest/checksums. Он соседствует с `../mlflow/`, а не входит в tracking store.
Данные, исходные строки и manifests с приватными ID игнорируются Git.

Опциональные локальные слои ETL: `raw/` (копия неизменяемых входов, обычно удобнее
внешний read-only dataset), `features/` (point-in-time snapshots), `quarantine/`
(сохранённые parsing/quality ошибки). Их наличие не означает готовый ETL.
Labels хранятся отдельно от serving features, будущие исходы не доступны inference.

Для [08_MY_EDA.ipynb](../notebooks/08_MY_EDA.ipynb) в `raw/` нужны восемь распакованных
`ext-journal-YYYY.csv` (2019–2026) и четыре CSV: справочник состояний,
справочник каналов, журнал-пример и справочник объектов. Локально можно создать
ссылки на неизменяемые файлы внешней папки вместо копирования примерно 16 ГБ;
`raw/` целиком исключён из Git. Блокнот проверяет наличие входов и ожидаемые
заголовки, читает CSV напрямую, а архивы `.7z` могут оставаться рядом для
проверки происхождения. Ссылки зависят от исходного локального пути: при переносе
внешней папки их надо пересоздать.

Для восьмилетней подготовки `journal-curated-v4` нужны исходные
`ext-journal-YYYY.7z` в `raw/`; исследовательский годовой Parquet не является
входом. Два переданных XLSX скопированы в `raw/maintenance/` и остаются вне Git.
Их контрольные SHA-256, разбор планов 2026 и предупреждение о конфликте года
вкладки — в локальном `../artifacts/maintenance-2026-planned/manifest.json`.
Плановые строки не присоединены к событиям и не задают подтверждённую метку.

Требования к новому набору — [DATA-01–DATA-07](../../docs/REQUIREMENTS_SPEC.md#data--вход-и-происхождение),
схема/manifest/accounting — [контракт DATA](../../docs/DATA.md#контракт-следующего-etl).
Физическая структура snapshot уточняется до P-01; каталог не фиксирует её автоматически.
