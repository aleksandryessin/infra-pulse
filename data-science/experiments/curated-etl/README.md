# Сырой журнал → curated: правило сверки до сопоставительного прогона

23.09.2026. Этот протокол записан до первого сопоставления итогов ETL с замером F1.
Первый технический прогон только архива 2026 не вычисляет ни одно из трёх опорных
чисел F1. Никакая модель не обучается (`models_fitted = 0`).

> **Публичная версия.** ETL (`curate_journal.py`, `finalize_curated_partial.py`) и сверки
> DATA-03 входят в репозиторий. Сопоставление с газовой постановкой F1, аудит совместного
> молчания, ноутбуки 06/07 и их отчёты относятся к этапу до итогового решения и в
> репозиторий не входят; ниже они упоминаются без ссылок.

## Воспроизведение

Из корня репозитория после `uv sync --locked --group train --group research`:

В исполненном локальном запуске `uv sync` не завершился из-за недоступного DNS
PyPI; использована уже существовавшая `.venv` с тем же lock. Команды ETL и
аудитов фактически запускались через `.venv/bin/python`, итоговый `make check` —
через `UV_NO_SYNC=1 make check`. При доступной сети `uv sync` остаётся штатной
установкой.

```sh
uv run --locked --group train --group research python \
  data-science/scripts/curate_journal.py \
  --source /absolute/path/to/dataset \
  --output data-science/artifacts/curated-except-2021 \
  --years 2019 2020 2022 2023 2024 2025 2026 \
  --ingested-at 2026-09-23T14:36:00Z

uv run --locked --group train --group research python \
  data-science/scripts/compare_f1_anchors.py \
  --snapshot data-science/artifacts/curated-except-2021 \
  --output data-science/reports/f1-anchor-comparison-2026-09-23.json

uv run --locked --group train --group research python \
  data-science/scripts/verify_source_parquet.py \
  --source /absolute/path/to/dataset \
  --snapshot data-science/artifacts/curated-except-2021 \
  --output data-science/reports/source-parquet-verification-2026-09-23.json

uv run --locked --group train --group research python \
  data-science/scripts/audit_silence_colocation.py \
  --snapshot data-science/artifacts/curated-except-2021 \
  --output data-science/reports/silence-colocation-2026-09-23.json

uv run --locked --group train --group research python \
  data-science/scripts/audit_state_reference.py \
  --catalogue /absolute/path/to/справочник_состояний.csv \
  --snapshot data-science/artifacts/curated-except-2021 \
  --output data-science/reports/state-reference-audit-2026-09-23.json
```

В команде пример `--source` заменяется локальным read-only каталогом сырья;
абсолютный путь не сохраняется в агрегированном отчёте. Для побитового повтора
указываются тот же вход, код и `--ingested-at`, но другой `--output`.
Проверка старого Parquet сравнивает 7z CSV и производную выгрузку по числу
записей, крайним датам, булевому alarm и фиксированной выборке `event_id % 10000 = 0`;
это контроль содержимого, а не DATA-03 provenance старого конвертера.

23.09 проверка нового ответа заказчика выявила, что служебные значения
`01.01.1970 03:00:00/01` массово лежат в `значение_датчика`, а не только во
времени события. Версия `journal-curated-v3` помечает обе формы, оставляет
исходный текст и исключает эти записи из временных последовательностей. Предыдущий
локальный v2 snapshot признан устаревшим и не публикуется как текущий.
Позднее добавленный `справочник_состояний.csv` проверен отдельным аудитом:
62 строки, четыре поля без числового порога/единицы/даты действия/привязки к
каналу; три точных дубля и один противоречивый alarm. Газовую целевую лексему
он не содержит; по типу и точной лексеме потенциально совпадают 323 250 из
653 835 текстовых газовых записей выбранного среза. Без связи набора с каналом
это верхняя оценка. Это частичный reference, а не основание перекодировать
принятый raw ETL или изменить F1. Заказчик подтвердил ППР с баллонами и
переносные измерения до/после сварки, но график ещё не получен: доля лексем
при проверках неизвестна.
После второго полного прогона:

```sh
uv run --locked --group train --group research python \
  data-science/scripts/verify_curated_repro.py \

  --second data-science/artifacts/curated-except-2021-repeat \
```

Проверяются SHA-256 каждого выходного файла и идентичность manifest без

Исполненный повтор подтвердил **393/393 одинаковых SHA-256** и равенство
нормализованного manifest; [сводка](../../reports/curated-repro-2026-09-23.json).
Локальные curated, quarantine, dedup, исключения и словарь лексем находятся
только в ignored `data-science/artifacts/`. Последний хранит текстовые категории
и не копируется в Git. Сводный manifest публикуется в `reports/` после приёмки.

без outputs. В этой локальной среде Jupyter kernel не смог открыть loopback

## Исполненный результат и проверки

На семи архивах 2019, 2020, 2022–2026 прочитано 259 847 069 CSV-записей,
включая один повтор заголовка 2025: 259 847 068 приняты, 884 273 точных
дубля, 258 962 795 curated. Обе сверки DATA-03 сошлись по каждому архиву и
итогу; карантин пуст. 2021 не читался. 6 105 469 записей без канала в текущем
справочнике сохранены с `unknown`, а 3 366 603 timestamp-группы с разными
значениями сохранены раздельно. [Отчёт ETL](../../reports/curated-etl-2026-09-23.json).

DuckDB использовал одно соединение, 2 threads и `memory_limit=4GB`;
peak RSS процесса первого прогона — 10 092 MB, elapsed 1 590 с. Второй
полный прогон: 393/393 побитово одинаковых файлов и тот же manifest без
переменного блока `runtime`, elapsed 1 606 с, peak RSS 11 151 MB.
Прямая [сверка 7z с прежним Parquet](../../reports/source-parquet-verification-2026-09-23.json)
совпала по числу событий, минимуму/максимуму даты и alarm в каждом из семи лет,
а также на детерминированной выборке 26 182 полных исходных записей. Она не
доказывает полную эквивалентность нормализации прежнего конвертера.

По предзаписанному правилу F1 пересчитан
на curated: positives 3 810 вместо 3 825, цензурирование 26.6% без изменения,
B0 AUC 0.8663 вместо 0.8668. Вердикт остаётся `N`: 529/529 каналов с positive,
26.6% цензурирования при пороге 25%, квартальный размах 5.75× при пороге 5×.
Неизвестный исход по периоду — 58.1%; потолок recall по построению — 0.853.
R3/O2 остаются историческими результатами на производном Parquet.

`UV_NO_SYNC=1 make check` для кодового diff: lint, format и imports прошли,
**253 passed**, 7 прежних предупреждений зависимостей/Matplotlib. Tracked
notebook 06/07 без outputs; по три code cells исполнены в ignored копиях.
Повторы аудита молчания, F1, сверки 7z/Parquet и справочника состояний дали
побитово одинаковые reports вне `runtime`.

## Отдельный восьмилетний слой v4, 25.09

По поручению команды `curate_journal.py --years 2019 … 2026 --policy
exclude-2021-apr-jun-v1` подготовил **все типы каналов** из CSV внутри исходных
архивов. Выход остаётся в игнорируемом Git
`artifacts/curated-all-sensors-exclude-2021-q2/`; команда запуска в
[README исследовательского контура](../../README.md). Это отдельный snapshot,
а не ретроспективная замена семилетних F1-результатов.

[Агрегированный отчёт](../../reports/prepared-data-2026-09-25.json):
313 546 017 входных логических записей с одним повтором заголовка,
13 788 616 исключённых за апрель–июнь 2021, карантин 0, 942 048 точных
дублей и 298 815 352 curated; обе формулы DATA-03 сошлись по всем восьми
архивам. 90 помесячных разделов, календарь, текущий справочник с unknown,
сырые `value_raw`/`alarm`, nullable `value_numeric` и quality flags сохранены.
453 хеша выходных файлов находятся в локальном manifest; размер snapshot
14.58 GB. Пропуски полного календарного дня: 07–08.04.2024 и 01.06.2026.

Первый полный процесс построил все месяцы, но глобальный `COUNT(DISTINCT
event_id)` вспомогательного аудита превысил 4 GB DuckDB и не опубликовал
snapshot. [`finalize_curated_partial.py`](../../scripts/finalize_curated_partial.py)
проверил stage и каждую категорию каждого месяца, архивные контрольные числа,
хеши и покрытие, затем атомарно опубликовал snapshot. Основной ETL теперь
считает повтор ID только внутри месяца; точные дубли содержимого по-прежнему
учтены. [Полный повтор v4](../../reports/prepared-repeat-2026-09-25.json)
заново прочитал все архивы за 1869.301 с с peak RSS 10 765.5 MB;
453/453 выходных SHA-256, source hashes, coverage, policy, reference и
счётчики совпали с первым опубликованным snapshot.
Файловые времена дают около 76 минут от создания partial до публикации,
включая устранение ошибки; recovery занял 8.816 с, peak RSS 319.4 MB.

Отдельный [аудит качества](../../scripts/audit_prepared.py) сохраняет локально
помесячные агрегаты по типам датчиков: объём, исходный alarm, словарь текстов,
unknown reference, epoch/sentinel candidates, пропуски, совпадающие timestamps
и концентрацию по каналам. В июле 2021 осталось 7 032 исходных газовых
`alarm=true`, 6 940 из них с «Неисправен», против 40/95 в том же месяце
2020/2022. Эти месяцы доступны для анализа, но не приняты для обучения.
Плановые XLSX 2026 и диагностический каталог состояний подготовлены отдельно;
они не присоединены к событиям. Будущий суточный таргет может использовать
сохранённый raw `alarm`, но единица прогноза и наблюдаемость ещё не зафиксированы.

После просмотра месячных долей добавлен **отдельный**, не меняющий v4
[research overlay](../../reports/alarm-spike-policy-2026-09-25.json):
февраль–март 2020 для всех типов, только газ 02.07.2021 и 06.11.2025.
Последний пик относится к ноябрю 2025, хотя на графике близок к метке 2026.
Исключённые curated-строки и policy-календарь сохранены локально с provenance;
повтор overlay дал 5/5 одинаковых хеша. Периоды выбраны после просмотра
исходных тревог, поэтому `test_2025` уже не слепой holdout. Это не
доказательство ложных alarm и не снимает R-2021.

## DATA-03 gate

Для каждого прочитанного архива и сводного выбранного входа:

```text
N_input_records = N_accepted + N_quarantine + N_technical_headers + N_out_of_scope
N_accepted = N_curated + N_dedup_removed
```

Расхождение с опубликованным числом **записей событий** исходного архива
(2019 20 993 328; 2020 28 172 398; 2021 53 698 948; 2022 43 483 149;
2023 31 937 125; 2024 49 023 883; 2025 55 541 796; 2026 30 695 389)
или несходимость DATA-03 означает дефект импорта и запрещает статус accepted.
В 2025 один повтор заголовка делает `N_input_records` на 1 больше числа событий;
сверка контрольного числа использует `N_input_records - N_technical_headers`.
Непрочитанный архив перечисляется, но в обе суммы не входит. В этой задаче 2021
не запускается: R-2021.a рассматривается только после принятого одинакового ETL.

## Правило сопоставления с предшествующими вердиктами

После принятого ETL за 2023–2026 на **том же** cutoff/scope F1 воспроизводятся
три опорные величины: 3 825 positive канало-суток, 26.6% цензурированных
eligible канало-суток, AUC пола B0 `heard_days_30d` 0.8668.
**Любое расхождение** хотя бы одной величины после округления до опубликованной
точности ведёт к перезапуску соответствующих аудитов и перепроверке вердиктов
R3/O2/N. Само по себе расхождение не считается дефектом импорта. Если не выполнен
DATA-03 gate, численное сравнение и вывод по вердиктам не публикуются.

Отчёт должен хранить хеши сырья, справочников, конфигурации и кода, Git SHA,
состояние diff, elapsed и peak RSS. Сравнение содержимого повторного прогона
игнорирует только runtime; `ingested_at` фиксируется параметром запуска.

## Цензурирование по объекту × пикету

Предрегистрированное решающее правило
зафиксировано до первого различающего запроса. Плацебо и операции перестановки
переиспользуют аудит лексемы. Результат —
ассоциация в пространстве и времени, не диагноз шлюза или электропитания.

На принятом curated: 24 708 газовых начал суточного молчания; у 9.39% совпало
начало молчания другого канала того же объекта/пикета, у 9.21% была запись
`Обесточен` на участке в эти или предыдущие сутки (2 275 якорей). Сильнейшие
пространственные плацебо — 46.03% и 40.87% соответственно. По записанному
правилу итог **`does_not_discriminate`**: журнал не различает падение шлюза и
отключение участка после события. Агрегированный отчёт.

Для новой информации заказчика есть отдельные аналитические предложения:
аналитика данных — о разметке, технолога — о группировке и очереди.
Оба документа имеют статус proposed; они не меняют действующий F1 таргет и
не объявляют ответы представителя заказчика принятыми решениями D01/D05/D06.
