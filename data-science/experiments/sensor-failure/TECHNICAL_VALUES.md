# Технические значения каналов: `technical_value` (`sensor-technical-values-v1`)

26.09.2026. Статус: **implemented как правило строки; черновик, выбран на
development** (2019–2020, 2022–2024). Validation и позже не использовались.
Метка — зарегистрированное техническое значение, а не подтверждённая поломка.
Протокол: [README.md](README.md). Требование ML-02/ML-03 (определение до fit);
D01/D05/D06 открыты.

Файлы: [конфигурация](../../configs/sensor_technical_values_v1.json),
`modeling/sensor_technical_values.py`, `tests/test_sensor_technical_values.py`.

```python
technical_reason_sql(alias="e", config=None) -> str   # 'text_code' | 'epoch_value' | 'code' | 'below_range' | 'above_range' | NULL
technical_value_sql(alias="e", config=None) -> str    # boolean
measurement_exclusion_sql(alias="e", config=None) -> str  # technical AND NOT alarm
load_config(path=None) -> dict
```

Выражения используют `sensor_type`, `value_numeric`, `value_raw` (и `alarm` —
только в `measurement_exclusion_sql`). Значение — `value_numeric`, иначе
`value_raw` как число (запятая допускается). Проверка по порядку: текстовое
значение → эпоха → код (допуск 1e−6) → ниже диапазона → выше диапазона. Границы
диапазона допустимы. Незнакомый тип датчика → NULL.

## Правило

| Тип | Технично | Основание |
| --- | --- | --- |
| Все настроенные числовые типы | коды −100, 255, −127, −3276, −255 | ответы организаторов |
| Датчик температуры | вне [−40; 85] °C; текст `Не определено` | proxy: типовой промышленный диапазон и данные; паспорт изделия не получен. Чувствительность — [−55; 125] (открытый паспорт 1-Wire термометра DS18B20; применимость к датчикам заказчика не подтверждена) |
| Газовый датчик | < 0 или > 100 % об.; коды 2,55, −2,56, 327,68 | физика объёмной доли; единица — % об. метана (ответ заказчика). Коды — гипотеза по данным: значения = целое × 0,01 (255, −256, 32768) |
| ИБП | вне [0; 100] | proxy «по данным»; смысл величины не подтверждён |
| Состояние охраны | значение, начинающееся с `01.01.1970 03:00` | эпоха — техническое значение по ответу организаторов; встречается как значение, не как время |

НКПР метана 4,4 % об. (IEC/ГОСТ 60079-20-1) — уровень тревоги, не граница
достоверности; уставка 1 % — не граница диапазона.

**Правило `тревожное`.** Технический статус от `alarm` не зависит.
По ответу организаторов служебное значение исключается из измерений, только
если запись не тревожная. Для этого есть `measurement_exclusion_sql`.
На development числовые строки всех трёх типов **ни разу** не имеют
`alarm=true`. Тревога стоит на парной текстовой строке того же timestamp:
`Не определено` — alarm в 86% строк. Поэтому builder меток должен оценивать
тревожность на уровне «канал × timestamp».

## Каталог на development

**Температура** (683 873 числовых строк, 592 канала):
- `-127` — 5 175 timestamp на 341 канале, ежегодно 537–1 794 строк.
  - 97% — одиночное значение между двумя нормальными и одинаковыми.
  - 5 225 из 5 227 timestamp с `-127` имеют `Не определено` в тот же момент.
- `-3276` — 7, `-3260` — 28, `255` — 2 timestamp. Значения `-100` и паспортного
  85,0 нет: пика на 85 нет.
- Ниже −40: 2 201 строк на 8 каналах, в основном на 2–3 каналах сериями до
  40 показаний.
  Выше 85: 1 068 строк, скачок от предыдущего в среднем 55 °C.
- `Не определено` (6 744 строк) всегда делит timestamp с числом:
  - `-127` — 5 225, < −40 — 1 173, > 85 — 231, в диапазоне — 212, 0 — 2;
  - итого 96,9% — код или выход за диапазон. Поэтому текст включён в правило.
  - `Неопределен` — другое, частое и нетревожное состояние; в правило не входит.
- `0,0` отмечен `sentinel_candidate` (2 015 timestamp на 247 каналах). 62% —
  одиночные значения между |t| ≥ 3 °C, 33% — рядом с околонулевыми. Это
  правдоподобное показание; в правило не входит, только чувствительность.

**Газ** (115,4 млн числовых строк, 456 каналов; значения кратны 0,01):
- Источник передаёт по изменению: одинаковые подряд значения — ≤ 0,1%.
- **0,0 — нормальный ноль.**
  - 85% (2019) и 97% (2023) нулей следуют за шагом ±0,01, а 70–88% значений
    0,01 — за нулём. Это дребезг на шаге разрешения, а не провал.
  - Одиночные нули между значениями ≥ 0,05: 0,03–0,07% нулей.
  - `Неисправен` в ±10 мин от нуля — 0 в выборке.
  - Доля нулей по каналам: медиана 11%, p90 46%; ни одного канала > 95%.
- Отрицательные значения только в 2020-10…12 (1 005 704 строк, 27–28 каналов;
  до этого — 0). Это одновременный сдвиг нуля, при разметке — массовый эпизод.
- Коды 2,55 и −2,56 — одиночные выбросы между значениями около 0 (96–100%),
  2020-10…12 и 3 строки в 2022. `327,68` — 1 строка.
- Значения 2–5,8 % об. нарастают (предыдущее ≥ 0,5 в 98%). Это похоже на
  реальные показания или поверочный газ, поэтому они не технические.

**ИБП** — 3 290 строк на 40 каналах, 0–100, в основном 3–10. Технических
значений нет.

**Эпоха.** Встречается только как значение `Состояние охраны` (46 055 строк,
29 из 46 каналов, alarm 0) и у строк без типа. `is_epoch_placeholder` отмечает
ровно эти строки, их время события парсится нормально. Время-эпоха на
development не встречается.

## Решения и сомнения

- **Газ 0,0** — нормальное показание, не техническое.
- **Газ как метка отказа.** Технические события газа почти целиком — один
  эпизод 2020-Q4. Для 2022–2024 метка газа по значениям практически пуста.
- **Эпоха у `Состояние охраны`.** Покрывает 43% канал-суток этого типа
  (около 190 суток в год на каждом из 29 каналов). Это устойчивое состояние,
  а не событие. Причина `epoch_value` включена по поручению; для основной
  метки её **рекомендуется исключить** или вынести в отдельный анализ.
- **«Застрывшее значение»** при передаче по изменению неотличимо от тишины.
  Вывод дан по газу: серий одинакового значения ≥ 24 ч в 2023 — 91, ≥ 7 сут — 5.
  Только чувствительность.
- **Не подтверждены:** модель и паспорт датчиков, диапазон ИБП, масштаб газовых
  кодов. Верхняя граница температуры 85 °C может отсекать реальный нагрев
  (организаторы упоминают внешний нагрев).
- `is_epoch_placeholder` исключает строки, у которых время корректно.
  Это влияет на реестр и признаки `subsystem-alarm-v1` для `Состояние охраны`.
